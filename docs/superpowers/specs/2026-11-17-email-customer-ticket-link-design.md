# 자동화 메일에 고객용 티켓 바로 열기 링크

작성: 2026-11-17

## 의도

티켓 자동화 메일(직원 답변 알림, 상태 변경 알림 등)을 받은 **티켓을 접수한 고객**이
메일 안의 링크를 눌러 로그인 없이 그 티켓을 바로 열어 보고 댓글을 달 수 있게 한다.
지금 메일은 "티켓을 확인하세요"라고만 해서 고객이 홈페이지 위젯을 찾아 들어가야 한다.

직원은 이미 `{{ link }}`(관리 화면 주소)로 바로 열 수 있으므로 대상이 아니다.

## 목표

- 메일 템플릿에 `{{ customerTicketLink }}`를 넣으면, 메일을 받는 고객마다 **그 고객 전용** "티켓 열기" 링크(`<a>` 태그째)가 들어간다.
  링크를 못 받는 사람의 메일에서는 그 자리가 통째로 빠진다.
- 링크를 누르면 이미 있는 위젯 "새 탭에서 보기" 화면(`{WIDGETS_DOMAIN}/ticket-view#열쇠`)이 열린다 —
  진행 상황·설명·첨부·처리 기록·댓글 보기와 댓글 달기가 위젯과 같다.
- 링크로 단 댓글은 그 메일을 받은 고객 이름으로 등록된다.
- 링크는 **메일을 보낸 뒤 14일** 동안 열린다(사용자 결정: 메일은 늦게 여는 경우가 많다).
- "Send Email" 버튼 발송, 직원 댓글 10분 뒤 자동 발송(003) 모두 같은 자동화 메일이라 함께 적용된다.

## 하지 않을 것

- 새 화면을 만들지 않는다(기존 `/ticket-view` 그대로).
- 직원용 링크(`{{ link }}`)는 바꾸지 않는다.
- 만료된 링크를 메일로 다시 받는 기능은 만들지 않는다(검토한 C안, 이번 범위 밖).
- 위젯 "새 탭에서 보기" 링크는 **미사용 만료만 하루 → 2일**로 바꾼다(사용자 결정). 최대 7일·발급 빈도 제한·열 때 권한 재확인 없음은 그대로.

## 실패로 볼 것 (anti-goals)

- 받는 사람이 그 티켓의 고객이 아닌데(직원 메일 주소, 다른 회사 사람) 고객 링크가 들어가는 것.
- 한 고객의 링크로 다른 고객 이름의 댓글이 달리는 것.
- 메일 발송 기록(emailDeliveries)·로그에 열쇠 원문이 남아, 관리 화면을 보는 사람이 고객 링크를 얻는 것.
- 링크 발급이 실패했다고 메일 자체가 안 가는 것.

## 정해진 것 (사용자 결정)

- 유효 기간: **B안 — 보낸 뒤 14일**. (A: 위젯과 같은 하루/7일 — 늦게 열면 만료. C: 만료 화면에서 새 링크 받기 — 일이 많음.)
- 만드는 방법: **1안 — 받는 고객마다 각자의 링크**. (2안: 티켓에 링크 하나를 첫 번째 고객 몫으로 만들어 모두에게 — 간단하지만 여러 고객·직원이 같이 받으면 댓글 작성자가 틀어지고 직원 메일함에도 고객 링크가 들어감.)
- 메일 속 모양: **(b) 링크 태그째 넣고, 없으면 통째로 뺀다**. (a 주소만 — 빈 문장·빈 버튼이 남음, c 대신 문구 — 문구 관리가 늘어남.)
- 직원 계정(user)이면 고객 기록이 있어도 **링크를 넣지 않는다**.
- 메일 링크는 **열 때 권한을 다시 확인**한다(발급 때와 같은 기준). 5분에 한 번만 다시 확인한다.
- 위젯 링크 미사용 만료: **2일**.

## 지금 구조 (고칠 곳)

- **automations-api** `src/common/emailUtils.ts`
  - `generateDoc`에서 템플릿 내용의 자리표시자를 `automations.replacePlaceHolders`(tickets-api)로 바꾼 뒤,
  - `sendEmails`가 받는 사람마다(`for (const toEmail of toEmails)`) 한 통씩 보낸다.
  - 보내기 전에 `customerMapByEmail`(메일 주소 → 고객 정보)을 이미 만들어 둔다.
  - SES 설정 시 `emailDeliveries.create`로 본문(`body: customHtml`)을 저장한다.
- **tickets-api**
  - 자리표시자 값: `src/automations/getRelatedValue.ts`(`link`가 여기서 관리 화면 주소로 바뀜), `src/automations/index.ts`.
  - 링크 열쇠: `src/ticketViewLink.ts`(규칙, 순수 함수), `src/models/TicketViewLinks.ts`, `src/models/definitions/ticketViewLinks.ts`,
    `src/ticketViewRpc.ts`(발급 권한 판단 `createTicketViewLink` — 위젯 목록과 같은 기준), `src/messageBroker.ts`(RPC 등록).
- **widgets** `client/ticketview/TicketViewPage.tsx`: 만료 안내 문구가 "위젯에서 '새 탭에서 보기'를 다시 눌러 주세요"뿐이다.

## 설계

### 1. 메일용 링크 (tickets-api)

- 링크 문서에 종류 `kind: 'widget' | 'email'`을 둔다(기존 문서는 없음 = widget).
- 메일용 링크 규칙
  - `expiresAt = 발급 시각 + 14일`, 사용해도 **늘리지 않는다**(고정).
  - 위젯의 "발급 후 최대 7일" 제한을 적용하지 않는다(14일이 최대).
  - 고객당 1분 발급 제한(위젯용 남용 방지)은 적용하지 않는다 — 서버가 메일을 보낼 때만 발급하고 고객이 부를 수 없다.
  - 같은 티켓·고객의 메일용 링크는 최근 **20개**까지 남기고 오래된 것부터 폐기한다(위젯 링크 상한 5개와 따로 센다).
    답변이 잦아 메일이 많이 가도 2주 안의 메일 링크는 대부분 살아 있게 하려는 값.
- 발급 권한은 위젯과 같은 판단(`createTicketViewLink`의 기준: 티켓 고객, 연결된 고객, 같은 회사 공개 티켓 등)을 그대로 쓴다.
  권한이 없으면 링크를 만들지 않는다.
- 새 RPC `tickets:ticketView.createEmailLink` `{ ticketId, customerId }` → `{ token }` 또는 `null`(권한 없음·티켓 없음).
  오류를 던지지 않고 `null`로 답한다(메일 발송이 멈추지 않게).
- **열 때 권한 재확인(메일 링크만)**: 열쇠를 쓸 때(`useTicketViewLink` — 상세 보기·댓글 달기) 발급 때와 같은 기준
  (① 티켓 고객 목록 ② 연결된 고객 ③ 공개 티켓 + 같은 회사)을 다시 본다. 판단 로직은 발급과 한 함수로 공유한다.
  - 5분에 한 번만 다시 본다(기존 연장 기록 주기와 같음). 마지막 확인 시각을 링크 문서에 둔다.
  - 통과하지 못하면 만료와 같이 취급한다(티켓 내용 없이 만료 안내). 권한이 빠진 뒤 막히기까지 최대 5분.
- **위젯 링크 미사용 만료 2일**: `TICKET_VIEW_LINK_TTL_MS`를 2일로. 위젯 쪽이 만료 1시간 전에 새로 받는 규칙
  (`widgets/client/messenger/components/ticket/openTicketView.ts`)과 관련 주석·테스트를 함께 맞춘다.

### 2. 자리표시자 바꾸기 (automations-api)

- `generateDoc` 단계(티켓 전체에 한 번)에서는 `{{ customerTicketLink }}`를 **바꾸지 않고 남겨 둔다**.
  (지금 replacePlaceHolders가 모르는 이름을 어떻게 다루는지 확인 필요 — 지우거나 '-'로 바꾸면 안 된다.)
- `sendEmails`에서 받는 사람마다 보내기 직전에:
  1. 본문에 `customerTicketLink`가 없으면 아무것도 하지 않는다(지금과 같음, 추가 요청 없음).
  2. 있으면 `customerMapByEmail[toEmail]`로 고객을 찾고, 티켓 자동화(대상이 티켓)일 때만 1의 RPC로 열쇠를 받는다.
  3. 받으면 `<a href="{WIDGETS_DOMAIN}/ticket-view#{token}">티켓 열기</a>`(단순한 버튼 모양 인라인 스타일)로,
     못 받으면(고객 아님·직원 계정·권한 없음·발급 실패) **빈 문자열**로 바꾼다.
     - 받는 사람이 직원 계정(core `users`에 같은 메일 주소)이면 고객 기록이 있어도 발급하지 않는다.
     - 템플릿 작성자가 `href="{{ customerTicketLink }}"`처럼 넣은 경우(편집기가 `%7B%7B…%7D%7D`로 바꿔 저장할 수 있음)는
       지원하지 않는다고 안내하고, 그 형태는 빈 값으로 바꾼다 — 태그째 넣는 방식만 쓴다.
  4. 그 받는 사람의 메일에만 바꾼 본문을 쓴다.
- 발송 기록(`emailDeliveries.create`의 `body`)에는 **바꾸기 전 본문**(자리표시자 그대로)을 저장한다 — 열쇠 원문이 기록에 남지 않게.
- 디버그 로그에도 바꾼 본문·열쇠를 찍지 않는다.
- 위젯 공개 주소는 환경 변수 `WIDGETS_DOMAIN`(gateway·core·inbox-api에서 이미 쓰는 이름)을 automations-api에서도 읽는다.
  없으면 고객 링크를 넣지 않는다(빈 문자열).

### 3. 템플릿에서 고를 수 있게

- 자동화 메일 템플릿의 티켓 속성 목록(지금 `link`가 나오는 곳)에 `customerTicketLink` — "고객용 티켓 링크"를 추가한다.

### 4. 만료 안내 문구 (widgets)

- 만료 문서는 TTL로 지워져 어떤 종류 링크였는지 알 수 없으므로, 한 문구로 두 경우를 안내한다:
  "링크가 만료됐어요. 최근 받은 메일의 링크를 누르거나, 위젯에서 '새 탭에서 보기'를 다시 눌러 주세요."(영문도 같은 뜻)

## 남은 판단 (구현하는 사람 몫)

- `kind` 필드 이름·기본값 처리, 메일용 상수(14일, 20개) 위치 — `ticketViewLink.ts`의 순수 함수 규칙에 맞춰 단위 테스트로 고정.
- 같은 메일 안에 자리표시자가 여러 번 있으면 같은 링크로 모두 바꾼다.
- 받는 사람 수만큼 RPC가 늘어나는 비용: 고객 메일은 보통 1~2명이라 순차 호출로 충분.

## 확인 방법

- 단위 테스트: 메일용 링크 활성/만료(14일 고정, 사용해도 안 늘어남, 7일 제한 미적용), 상한 20개 정리, 열 때 권한 재확인(통과·거부·5분 안에는 다시 안 봄), 위젯 링크 2일 미사용 만료, 받는 사람별 본문 바꾸기(고객/비고객/직원 계정/발급 실패/자리표시자 없음), 발송 기록 본문에 열쇠 없음.
- 로컬 실동작: 템플릿에 `{{ customerTicketLink }}`를 넣은 자동화로 고객 메일 발송 → 메일 링크로 새 탭이 열리고 댓글이 그 고객 이름으로 등록되는지, 직원 수신 메일에는 링크가 비는지 확인.
