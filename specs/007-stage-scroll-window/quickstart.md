# Quickstart: 검증 가이드

## 1. 단위 테스트 (창 계산)
ui-tickets에는 테스트 러너가 없어 widgets의 jest로 실행:
```bash
cd widgets && node node_modules/.bin/jest --config '{"rootDir":"../packages/ui-tickets","testEnvironment":"node","transform":{"^.+\\.tsx?$":["<rootDir>/../../widgets/node_modules/ts-jest",{"tsconfig":{"esModuleInterop":true,"target":"es2019"},"diagnostics":false}]},"testMatch":["<rootDir>/src/boards/utils/__tests__/stageWindow.test.ts"]}'
```
기대: 전부 통과.

## 3. 실행 결과 (2026-11-16, 로컬, Playwright 휠 스크롤 자동화)
테스트 데이터: '접수' 단계에 `[스크롤테스트] 001~500` 티켓 500개 (로컬 DB, 남겨 둠).

| 항목 | 결과 |
|---|---|
| 화면 카드 수 최대 | 20 (#5 통과) |
| 001 → 500 내려가는 동안 목록 요청 | 25회, 모두 20개씩(skip 10, 30, … 490) (#2 통과) |
| 500 → 001 올라오는 동안 목록 요청 | 0회 (#3 통과) |
| 창 이동 시 보던 카드 위치 | 매 이동 카드 1개 이내 차이(예: 030 → 031) (#1 통과) |
| "이전 보기" 버튼 | 없음 (#4 통과) |
| 목록 요청 응답 | 중앙값 30~50ms. 약 10초마다 1~2초 걸리는 요청 있음 → 개발 모드 게이트웨이가 10초마다 `execSync`로 supergraph compose를 돌려 이벤트 루프를 막는 로컬 전용 현상(운영은 1회만 실행). 같은 요청 직접 반복 측정으로 시간 주기 확인 |
| 참고(기존 동작) | 카드 hover 상세 미리받기(TicketItem)로 스크롤 중 ticketDetail 요청 약 190회 발생 |

미확인: #6~#11(필터 변경, 다른 창 실시간 수정/삭제, 드래그, 마감일 이벤트, 드래그 반응), 터치 당기기.
