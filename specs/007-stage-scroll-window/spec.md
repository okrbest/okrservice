# Feature Specification: 티켓 보드 단계 컬럼 연속 스크롤

**Feature Branch**: `007-stage-scroll-window`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "티켓 보드 단계 컬럼 스크롤 개선. 설계: docs/superpowers/specs/2026-11-16-stage-scroll-window-design.md"

## 배경

티켓 보드의 각 단계 컬럼은 속도를 위해 카드를 한 번에 최대 20개만 보여준다. 지금은 아래 끝에 닿으면
20개가 통째로 바뀌고 스크롤이 맨 위로 튀며, 위쪽 카드를 다시 보려면 "이전 보기" 버튼을 눌러 서버에서
다시 받아야 한다. 운영자는 어디를 보고 있었는지 놓치고, 반응이 없다고 느껴 버튼을 반복해서 누른다
(Sentry Rage Click JAVASCRIPT-REACT-4 조사 결과). 가장 중요한 조건은 **느려지지 않는 것**이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 아래로 계속 스크롤하며 카드 보기 (Priority: P1)

운영자가 카드가 많은 단계 컬럼을 아래로 스크롤하면, 보던 카드가 사라지거나 화면이 맨 위로 튀지 않고
다음 카드가 이어서 나타난다.

**Why this priority**: 가장 자주 하는 동작이고, 지금 가장 불편한 지점(화면 튐)이다.

**Independent Test**: 카드 50개 이상인 단계에서 아래로 끝까지 스크롤하며, 매번 직전에 보던 카드가 같은 자리에 남는지 확인.

**Acceptance Scenarios**:

1. **Given** 단계에 카드 50개, 처음 20개가 보이는 상태, **When** 컬럼 맨 아래까지 스크롤, **Then** 다음 카드들이 이어서 나타나고 직전에 보던 카드는 화면에서 같은 위치에 유지된다.
2. **Given** 이미 한 번 받아본 구간으로 다시 아래로 내려가는 상태, **When** 맨 아래까지 스크롤, **Then** 서버에 다시 요청하지 않고 카드가 나타난다.
3. **Given** 마지막 카드까지 본 상태, **When** 더 스크롤, **Then** 아무 변화 없고 "더 보기" 버튼도 보이지 않는다.

---

### User Story 2 - 위로 스크롤해서 이전 카드 다시 보기 (Priority: P1)

운영자가 아래로 내려간 뒤 다시 위로 스크롤하면, 버튼 없이 이전 카드가 이어서 나타난다.

**Why this priority**: "이전 보기" 버튼 제거의 전제 조건이다. US1과 함께 있어야 의미가 있다.

**Independent Test**: 40번째 카드 근처까지 내려간 뒤 맨 위까지 스크롤해 1번 카드까지 돌아오는지, 그동안 서버 요청이 없는지 확인.

**Acceptance Scenarios**:

1. **Given** 21~40번째 카드가 보이는 상태, **When** 컬럼 맨 위까지 스크롤, **Then** 이전 카드가 이어서 나타나고 보던 카드는 같은 위치에 유지된다.
2. **Given** 위와 같음, **When** 위로 스크롤해 이전 카드가 나타남, **Then** 서버 요청이 발생하지 않는다.
3. **Given** 첫 카드가 보이는 상태, **When** 위로 스크롤, **Then** 아무 변화 없다.
4. 어떤 상태에서도 "이전 보기" 버튼은 보이지 않는다.

---

### User Story 3 - 바뀐 카드가 보관 구간에도 반영 (Priority: P2)

화면 밖으로 밀려난 카드가 그 사이 다른 사람에 의해 수정·이동·삭제되면, 다시 스크롤해 돌아왔을 때 바뀐 내용으로 보인다.

**Why this priority**: 서버에 다시 묻지 않는 대신 생기는 오래된 정보 문제를 막는다.

**Independent Test**: 화면 밖 카드를 다른 창에서 수정/삭제한 뒤 스크롤해 돌아와 확인.

**Acceptance Scenarios**:

1. **Given** 화면 밖으로 밀려난 카드 A, **When** 다른 사용자가 A의 제목을 수정 후 운영자가 스크롤해 돌아옴, **Then** 수정된 제목이 보인다.
2. **Given** 위와 같음, **When** 다른 사용자가 A를 삭제하거나 다른 단계로 옮김, **Then** 돌아왔을 때 A는 이 단계에 보이지 않는다.

---

### Edge Cases

- 필터(생성일, 담당자, 검색 등)를 바꾸면 이전에 받아둔 카드는 버리고 처음부터 다시 보여준다.
- 컬럼이 짧아 스크롤이 생기지 않으면 "더 보기" 버튼으로 다음 카드를 볼 수 있다.
- 빠르게 위아래로 스크롤해도 같은 구간을 중복 요청하거나 카드가 중복 표시되지 않는다.
- 보이는 구간에서 카드를 드래그해 옮기거나 새 카드를 추가한 뒤 스크롤해도 순서·개수가 어긋나지 않는다.
- 서버 요청이 실패하면 현재 카드는 그대로 유지되고 다시 스크롤하면 재시도된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 단계 컬럼은 동시에 화면에 그리는 카드를 최대 20개로 유지해야 한다.
- **FR-002**: 맨 아래 도달 시 다음 카드를 이어 보여줘야 하며, 한 번에 보이는 구간은 10개 단위로 이동해야 한다.
- **FR-003**: 서버에서 카드를 받을 때는 지금과 같이 한 번에 20개씩 받아야 하며, 이미 받은 카드를 다시 요청하지 않아야 한다.
- **FR-004**: 맨 위 도달 시 이전에 받은 카드를 서버 요청 없이 이어 보여줘야 한다.
- **FR-005**: 보이는 구간이 이동해도, 이동 전 보던 카드는 화면상 같은 위치에 있어야 한다.
- **FR-006**: "이전 보기" 버튼을 제거해야 한다. "더 보기" 버튼은 유지한다.
- **FR-007**: 필터 변경이나 단계 재조회 시 받아둔 카드를 버리고 처음 구간부터 보여줘야 한다.
- **FR-008**: 화면 밖에 받아둔 카드가 실시간 업데이트로 수정·삭제·이동되면 받아둔 내용에도 반영해야 한다.
- **FR-009**: 드래그 이동, 카드 추가/삭제, 전체 선택 등 기존 보드 동작은 지금과 같이 동작해야 한다.

### Key Entities

- **받아둔 카드 목록(단계별)**: 해당 단계에서 지금까지 서버에서 받은 카드 전체와 그 순서. 화면에는 그리지 않는다.
- **보이는 구간(단계별)**: 받아둔 목록 중 화면에 그리는 최대 20개의 시작 위치.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 어떤 스크롤 동작에서도 단계 컬럼에 동시에 그려진 카드는 20개를 넘지 않는다.
- **SC-002**: 카드 N개를 처음부터 끝까지 내려보는 동안 서버 요청 횟수는 지금과 같다(N/20회 이하). 위로 돌아가는 동안은 0회.
- **SC-003**: 구간이 이동할 때 보던 카드의 화면 위치 변화가 카드 한 개 높이 이내다.
- **SC-004**: 카드 100개 단계에서 끝까지 내렸다가 처음까지 올라오는 동안 버튼을 한 번도 누를 필요가 없다.
- **SC-005**: 드래그 시작 반응 속도가 변경 전과 같은 수준이다(체감 지연 없음).

## Assumptions

- 대상은 내부 운영자용 티켓 보드(ui-tickets) 단계 컬럼이다. 위젯·고객 포털은 범위 밖.
- 서버 코드는 바꾸지 않는다. 단계별 개수 캐시 수정(itemsTotalCountCacheKey)은 별도 작업이다.
- 상한 20개, 서버 요청 단위 20개는 그대로 둔다. 위치 표시("21–40 / 150")와 불러오는 중 표시는 이번 범위 밖.
- 받아둔 카드는 그 화면을 떠나면(파이프라인 전환, 새로고침) 버린다.
- 화면 밖 카드의 반영은 보드가 이미 받고 있는 실시간 업데이트에 의존한다.
